# SDX55 GNSS on OnePlus 8T with mainline Linux

Status: **working** (2026-11-10). The GNSS receiver inside the SDX55 modem can be
driven from the mainline kernel without Android's `libloc`, GNSS HAL or IZat
stack.

## Scope

- OnePlus 8T KB2000 ("kebab"), SM8250, Debian 13 arm64, kernel 7.2.
- SDX55 is attached over PCIe/MHI; QMI is reached over QRTR
  (`AF_QIPCRTR` = 42), service 16 (LOC), node 3, port 84
  ("Location service (~ PDS v2)").
- The AP side is a small QMI LOC client; satellite measurement, RF,
  calibration, MCFG and EFS remain the stock Qualcomm/OnePlus firmware.

## Result

Outdoor, stationary, 600 s:

| Metric | Value |
| --- | --- |
| NMEA lines | 3715 |
| Valid GGA | 460 (1 Hz) |
| Valid RMC | 444 |
| Visible satellites | peak 42 |
| Horizontal accuracy | HDOP 1.5 |
| Time to first fix | about 2 minutes (cold) |

Exact coordinates are omitted. The position was stable and consistent between
runs; the altitude field was 5.5 m in the reported sample but has not been
validated over long periods.

## Why earlier attempts saw zero measurements

Three collection-side issues, all reproducible:

1. **Session ownership.** LOC indications (NMEA, SV info, position report) are
   delivered only to the client that owns the LOC session. A separate
   `qmicli --loc-follow-*` process receives nothing. A single long-lived client
   must both start the session and read the indications.
2. **Engine lock enum.** Lock value `0` is invalid and leaves the engine in
   state 2. `none = 1` is required.
3. **Single-fix recurrence.** Without an explicit recurrence the engine runs a
   single fix and stops after the first result. Periodic fixes require
   `periodic = 1`, `intermediate report state = 1`, and an interval.

XTRA / A-GPS is still unavailable on this firmware build: `Inject Xtra Data`
(0x00A7) and `Inject Predicted Orbits` (0x0035) return
`general-error` / `invalid-parameter`.

## Minimal QMI LOC sequence

Frames over QRTR have no QMUX layer:

```text
header: <B flags> <H transaction> <H message-id> <H payload-length>
TLV:    <B type> <H length> <value>
```

Useful messages:

| Message | ID | Notes |
| --- | --- | --- |
| Register Events | 0x0021 | request all indication types |
| Start | 0x0022 | TLV 0x01 session, 0x10 periodic, 0x12 intermediate, 0x13 interval (ms) |
| Stop | 0x0023 | TLV 0x01 session |
| Position Report | 0x0024 | indication |
| GNSS SV Info | 0x0025 | indication |
| NMEA | 0x0026 | indication, TLV 0x01 ASCII sentence |
| Inject UTC Time | 0x0038 | u64 ms, u32 uncertainty, i32 source |
| Inject Position | 0x0039 | double lat, double lon, float accuracy, source |
| Set Engine Lock | 0x003A | u32: none=1, mi=2, mt=3, all=4 |
| Set Operation Mode | 0x004A | u32: default=1, msb=2, msa=3, standalone=4 |

A working sequence is: register events, set lock to `none`, set mode to
`standalone`, inject UTC time and a coarse position, then start with
`periodic=1, intermediate=1, interval=1000`. NMEA arrives asynchronously on the
same socket.

## Deployment shape

A small daemon owns the LOC session and publishes:

- an atomic JSON state file (`fix`, `lat`, `lon`, `alt_m`, `hdop`,
  `sats_used`, `sats_visible`, `speed_mps`, `track_deg`, engine state);
- a Unix stream socket carrying NMEA 0183, so GeoClue, gpsd bridges or custom
  clients can consume it;
- UTC time injection every 10 s, and a coarse cell position before the first
  fix;
- a watchdog that restarts the session if NMEA stops.

## GeoClue

GeoClue 2 can consume the NMEA socket directly:

```ini
[network-nmea]
enable=true
nmea-socket=/run/kebab-gps.sock
```

Two operational points:

- A client must request **exact** accuracy
  (`RequestedAccuracyLevel = 8`). With street-level accuracy (4), GeoClue
  deliberately does not start the NMEA source to save power.
- GeoClue waits for an agent for the client's user ID before returning a
  client. A small agent service is required in headless setups.

## Limitations

- No A-GPS/XTRA/SUPL; cold start is about 2 minutes and weak-signal starts are
  slower.
- No Wi-Fi or cell-tower fusion; only the optional manually supplied coarse
  cell position.
- No long-duration, walking/driving, power or thermal validation yet.
- This is not an Android GNSS HAL; it exposes host NMEA and GeoClue only.
- Dual-frequency, SBAS and RTK were not tested.

The private deployment also includes the daemon and systemd units; they are not
part of this public document.
