# 磁力计（MMC5603）打通：软磁矩阵布局错误、开机常驻与可用航向

日期：2026-11-10。适用范围：OnePlus 8T（kebab）主线 Debian 13，内核 7.2。

## 一、结果

磁力计**可用**：

- SSC 里注册出 `mmc5603x`，25 Hz 三轴齐全，典型读数 X ≈ −25 µT、Y ≈ −2.3 µT、Z ≈ −37.2 µT，
  合成 |B| ≈ 45 µT（地磁场量级）；
- 同时把加速度计声明回 SMEM，SSC 实例从 19 项涨到 **55 项**，`rotv` / `geomag_rv` 等算法实例出现，
  于是有了**与倾斜无关的绝对方位（航向）**；
- 开机自动生效，已用完整重启验证；
- 提供读数器：一条命令拿到航向/场强/三轴，或常驻发布 `/run/kebab-mag.json`。

## 二、根因：72 字节软磁矩阵的布局写错

11/09 的 E29 把磁力计注册进了 SSC，但 1368 条样本里 **Z 恒为精确 0**，
当时按“驱动不读 Z / 器件 Z 通道坏”查了三轮。真正的答案在 AP 侧喂给 DSP 的参数里：

原厂 DTBO（`/__overlay__/oplus_sensor/msensor@0`）声明 `parameter-number = 18`、
`soft-mag-parameter` 是 **72 字节**，身份阵为

```
[10000,0,0, 0,0,0, 0,0,10000, 0,0,0, 0,0,0, 0,10000,0]     ← 10000 在下标 0 / 8 / 16
```

而 E29 写进 SMEM 的是 `[10000,0,0,0, 10000,0,0,0, 10000,0,…]`（下标 0 / 4 / 8）。
按 3×3 读，后者第三行整行为 0 ⇒ **Z 被乘以 0**，与“X/Y 真实、Z 恒 0”完全吻合。
换成官方布局后，同一个驱动、同一个固件、同一个 listener，Z 立刻出数。

A/A+/E 三轮静态逆向的结论（驱动读 6 字节、无 Z-inhibit、无第二条读路径）本身没错——
错的是喂给它的矩阵，那不是反汇编里能看见的东西。

## 三、最小充分条件

| 条件 | 说明 |
|---|---|
| SMEM130 里声明 `sensor_id=2 / sensor_name=0x02(MMC5603)` | 让 DSP 实例化 `sns_mmc5603x` |
| `feature.parameter[0..17]` 写正确的 18 项软磁矩阵 | 否则对应轴被缩放到 0 |
| （可选）`vector[0]` 声明 `0x08(BMI260)` | 加速度计可用，进而带出旋转矢量 |

**不需要**改 listener（原厂 r31 就够）、不需要改内核、不需要碰 DT 或 persist。

## 四、航向是怎么算出来的

DSP 的 `geomag_rv`（磁力计 + 加速度计融合）给出四元数。验证方式是把同一时刻的芯片帧向量转进世界系：

| 向量 | `R·v` | 结论 |
|---|---|---|
| 加速度 (0.13, −0.11, 9.64) | (0.00, −0.00, **9.64**) | 重力落在 +Z |
| 磁场 (−25.2, −2.2, −37.3) | (−3.2, **+24.6**, −37.6) | 水平分量指向正北 |

两者同时成立说明：**四元数是绝对方位，且用的是芯片坐标系**（DSP 的 `orient` 配置是恒等）。
手机“上边缘”= 芯片 +X 轴，所以

```
heading = atan2(R[0][0] (东), R[1][0] (北))
```

只用磁力计、假设平放的 `atan2(−dx, dy)` 作为交叉验证，两者静止时相差约 6°，方向一致。

## 五、怎么用

```
sudo kebab-mag-ctl human      # 航向 + 场强 + 三轴
sudo kebab-mag-ctl read 2     # 采 2 秒，一行 JSON
sudo kebab-mag-ctl heading    # 只输出航向角
sudo kebab-mag-ctl start      # 可选：常驻发布到 /run/kebab-mag.json
```

直接调用脚本也可以：`kebab-mag-read.py --datatype accel --seconds 2` 等；
`--datatype` 支持 `mag` / `accel` / `gyro` / `gravity` / `rotv` / `geomag_rv`。

## 六、开机常驻与回退

`kebab-ssc-mag-gate.service` 在 `kebab-ssc-listener` 之前运行：
停 SLPI → `insmod` 写 SMEM130（三处共 84 字节）→ 起 SLPI。
任何一步失败都退回“无磁力计、其余传感器照旧”。

```
systemctl status kebab-ssc-mag-gate     # 门控状态
sudo kebab-mag-gate.sh stop             # 临时关掉
sudo kebab-mag-recover.sh               # 彻底回滚（卸模块 + 校验 SMEM 归零 + 重启 listener）
```

## 七、验证记录

| 场景 | 结果 |
|---|---|
| E31 试机（候选取 r32） | 247 条 / 25.00 Hz / status 全 3；X −25.5..−24.4、Y −3.0..−1.7、**Z −37.8..−36.4** |
| 原厂 r31 + 补丁 | 19 项，`mmc5603x` 在列；122 条三轴全非零 |
| 完整重启（boot `7ad719f2…`） | 单元 success，19 项，122 条 25.00 Hz，Z −37.8..−36.6 |
| 加回加速度计（E34） | **55 项**，`rotv`/`geomag_rv` 可用，航向 178.8° 且与平放公式 185.1° 相差 6° |
| 读数器自愈 | 停 gate 后写 error 记录，重开后 5 秒内恢复、时间戳年龄 0.0 s |
| 10 分钟连稳（n=120）| 航向 178.30°–178.40°、标准差 **0.044°**；\|B\| 44.26–46.09 µT；电池 94% 未掉 |

## 八、尚未验证

- **航向的绝对准确度**：需要人拿着手机做已知朝向的对照（本轮只做了向量自洽性验证）；
- **硬铁/软铁现场标定**：当前用官方身份阵，未做椭球拟合；
- **长稳**：10 分钟窗口已测（航向 178.30°–178.40°、标准差 0.044°、\|B\| 44.3–46.1 µT），小时级仍未测；
- **功耗**：读数器常驻时的实际耗电未做长时间测量（观察窗口内电池容量未变）。

## 九、回退

`kebab-mag-recover.sh` 会停用并停掉单元、卸载模块（模块自带 SMEM 前像恢复）、重启 listener，
并校验 SMEM130 回到全零 SHA `04f30102…`。回退后回到 18 项、无磁力计的原厂态。
