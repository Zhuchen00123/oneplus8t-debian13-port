## 打开和管理

在本 Windows 项目目录运行：

```powershell
.\scripts\Open-Dsh.ps1
```

脚本复用已有 CNB 专用 SSH 通道和私有配置，使用独立随机连接标识，严格核验手机主机密钥。只将 Windows `127.0.0.1:3080` 转发到手机回环，再自动打开带启动令牌的页面；保持命令窗口运行，Ctrl+C 关闭本次隧道。端口占用时用 `-WebPort 13080`。不新增公网 HTTP 入口，也不修改酒馆的中继配置。

只检测不打开浏览器：

```powershell
.\scripts\Open-Dsh.ps1 -Check
```

已实测返回 HTTP 200、34,846 字节 HTML。此脚本需要本机现有 Python 3.13、paramiko、OpenSSH 和私有 `local/` 配置；不是可公开复制给他人直接使用的入口。隧道断开时重新运行；没有声称本机访问脚本具备跨 CNB 地址变更的自动重连。

在手机 SSH 终端：

```sh
kebab-dsh status
kebab-dsh logs
kebab-dsh web-url
kebab-dsh shell
# 进入开发 shell 后：
dsh --version
source /srv/dsh/dev/venv/bin/activate
```

`web-url` 仅供用户主动获取当前认证地址，其令牌属于凭据，不贴到公开记录。手机本地浏览器也可打开此地址。`status` 和 `logs` 的常规输出不展示启动令牌。启停为 `kebab-dsh start|stop|restart`，仅操作 DSH。

一次性模型任务可用 `kebab-dsh run --profile headless '任务内容'`。它使用相同配置和默认模型，但不在 Web systemd 的资源／文件系统约束内；不要把这种命令的工具验收等同于已逐项验收 Web 会话中的所有工具。

## 模型接入

渠道为 `azure-clinepass`，按用户后续选择，默认改为 **`cline-pass/deepseek-v4.1-flash`**。安装时默认 MiMo v2.6 Pro 的配置已另存备份；变更后仅重启 DSH，并以不带临时模型覆盖的实际请求验证 Flash。读取酒馆当前 clinepass profile 所引用的准确 secret-id，生成独立 DSH 凭据副本；没有修改酒馆 key、模型设置或 Azure 服务。实际渠道是手机现有回环 `15994/v1` → 既有受限加密 SSH → Azure clinepass，不能误接 `18078` 的另一网关。

认证 `/v1/models` 返回 39 个总条目，本次选取其中 **18 个 `cline-pass/` 模型**写入 [配置模板](../config/dsh/cordis.patch.example.yml)。模板通过 `apiKeyEnv` 引用环境变量，不含实际 key；运行凭据在 `/srv/dsh/private/provider.env`。后续 Azure key 轮换时，这个独立副本需要同步更新。

适配使用 `llm-pi-ai` 的 OpenAI Chat Completions，`supportsDeveloperRole=false`、`maxTokensField=max_tokens`。32768 上下文／2048 输出是保守的应用设置，**不是已经验证的上游最大容量**。自动标题生成关闭，自动请求重试设为 0，避免首阶段额外请求或重试放大。遥测环境变量已关闭。

| 检查 | 结果与边界 |
| --- | --- |
| MiMo 文本（安装时默认） | DSH headless 返回 `DSH_CLINEPASS_OK`，exit 0，无 stderr |
| MiMo 读取工具 | 真实 `read` 调用读取工作区样例，`tool_result.status=completed`，返回 `DSH_PHASE1_FILE_READ_OK` |
| MiMo 执行工具 | 真实 `bash` 调用运行无副作用 Node 单行程序，返回 `DSH_BASH_TOOL_OK`，exit 0 |
| Flash 模型 | 安装时临时 patch 返回 `DSH_SECOND_MODEL_OK`；改为常驻默认后，不带临时覆盖的请求返回 `DSH_DEFAULT_FLASH_OK` |
| Web 认证 | 无凭据 HTTP 401；启动令牌换 cookie 后 HTML 200；`settings/describe` 返回 200 / ok |
| DSH 服务重启 | cookie 在 DSH 重启后仍有效、启动令牌变化；最终 enabled / active，NRestarts=0 |
| Windows 访问路径 | 新访问脚本经现有 CNB + SSH，认证页面 HTTP 200；没有操作用户 GUI 或宣称触控验收 |
| 基础服务 | 7 个已核验的酒馆、Azure 转发、限充、三模式、酒馆中继服务仍 active，MainPID 与安装前一致；未重启它们 |
| 资源采样 | 认证／设置操作后约 145 MiB，随后空闲采样约 110 MiB；根剩约 2.0 GiB，/srv 剩约 211 GiB；最高热区采样约 45.2°C；这些不是长稳基准 |

18 个模型是已认证列出并配置的清单，只有上述 2 个做了实际生成，不能声称全部都通过。工具验收走 headless，Web 浏览器完整交互、手机触控、所有 Web 工具约束、断网／Azure 故障恢复、整机重启及 24 小时稳定性尚未测试。

服务配置见 [kebab-dsh.service](../scripts/dsh/kebab-dsh.service)：普通用户 `dsh`，仅回环监听；/srv 挂载保护；自动失败重启；CPU 配额 100% 且不使用 CPU7；MemoryHigh 1 GiB / MemoryMax 2 GiB；严格只读系统和限定可写目录。常驻服务启动不等于模型一直运行，也不等于已具备主动跟进或定时执行闭环。

如需撤回常驻服务：

```sh
sudo systemctl disable --now kebab-dsh.service
```

保留 `/srv/dsh` 及账号供恢复，不删除会话、不卸载基础包，也不停止既有 Azure 或 CNB 服务。恢复配置前先备份后来新增的 DSH 会话，停 DSH、审查归档路径后恢复对应文件，不能直接覆盖新数据。整机、内核、分区、充电、温控、电源键与 USB 配置均不属于此阶段改动。
