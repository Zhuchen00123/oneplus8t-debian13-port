# 本机驱动修正

所有补丁都是源码差异，不包含可加载模块或内核二进制。默认应用列表在 sources.lock.json 的 local_kernel_patches 中。

| 补丁 | 作用 | 应用范围与证据 |
|---|---|---|
| 0001 | TCM 完整四字节头计数、报文边界与诊断限频 | 默认应用；主机实际函数 ASan/UBSan 回归通过，仍不能解释本机全部报文布局 |
| 0002 | 按运行配置解码 7 字节前缀 + 7 字节对象，修正命令 framing 和启停零 ACK 轮询 | 模块接管已真实触摸/重启验收；内建候选出现 BTF -22 与 USB 不可达，成组部署待复验；默认不自动应用 |
| 0003 | AMB655X DSC 每包两片，匹配本机厂商 DT 参数 | 显示修复之一；单独应用仍不点亮；默认不自动应用 |
| 0004 | 申请面板 reset GPIO，执行厂商高/低/高脉冲 | 与 0003 共同修复物理显示；默认不自动应用 |

0003 先于 0004；0002 以 r1 驱动为前像。手动应用先做 git apply --check 并核对当前源码前像，保持作者和文件许可。prepare-kernel 默认只应用 0001，显示补丁列于 manual_kernel_patches，触摸候选列于 candidate_kernel_patches。不要把这些列表混同。

TCM 的合法 14/21 字节报文并非固件损坏证据。解析需校验完整帧、位宽、对象数/编号、重复与坐标范围，再上报输入。候选不修改触摸固件或持久报告配置，不支持所有 TCM 多段/嵌套布局。

交接记录补充：同一个内建候选首次出现 ABL 错误画面，第二次进入内核后出现 phy_qcom_qusb2 BTF -22，USB 不可达。不能继续只写“ABL 永久拒绝镜像”。交接将 BTF 故障归因于只部署内核而仍保留旧模块；该归因还需成组复验。两个启动结果不同的原因未知。

内建路线的下一阶段必须核对自己的根模块树和 initramfs 嵌入模块，不能依据相同 kernelrelease 或 vermagic 宣称兼容。

## r2 成组 profile（2026-10-04）

`kernel_profiles.r2` 显式按 0001 → 0003 → 0004 → 0002-r2 应用，逐步核验源码前像。0002-r2 是同一内建触摸提交导出的标准 git 邮件补丁，保持作者，与旧 candidate 的功能一致；两个触摸补丁不能重复应用。默认 r1 路线保留。

成组 r2 实际 rootfs 578、持久 initramfs 200、RAM initramfs 8 模块字节一致，实机内建触摸和两次重启通过，无旧接管服务或模块依赖。历史失败候选仍用于记录，不代表当前 r2 未验证。长窗口报文拒绝和间歇误触根因尚未消除。[r2 验收](r2.md)。
