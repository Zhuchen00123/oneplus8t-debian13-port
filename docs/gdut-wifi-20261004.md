# GDUT Wi-Fi 首次接入（2026-10-04）

用户要求手机直接连接大学城/番禺校区 `gdut`，再准备远程访问。内核保持 `7.2.0-kebab-debian13-r2+`；本轮没有刷分区、改 USB 地址或登录密钥。

## 当前结果

- ath11k_pci / QCA6390 设备存在，无 rfkill 软/硬阻断；iw/rfkill/wpa_cli 位于 `/usr/sbin`，普通 SSH 的 PATH 不含该目录，不代表工具缺失。
- 实际扫描到六个 `gdut` AP，最强约 -48 dBm，目标网络无 RSN/WPA 加密。
- 新建权限 600 的 `wpa_supplicant-wlan0.conf`，仅包含公开 SSID、`key_mgmt=NONE`、`country=CN`、`update_config=0`；没有账号或密码。
- 接口专用 `wpa_supplicant@wlan0` 已启动并启用，wpa_state=COMPLETED，实际关联为 5 GHz；systemd-networkd 获得 IPv4、IPv6、默认网关及 DNS。USB 管理链路仍通。
- 认证前 HTTP 请求被网关 302 重定向到学校登录页，HTTPS 超时；与下文认证后验证分别记录。

## 用户认证入口

[学校无线指引](https://nic.gdut.edu.cn/info/1029/2396.htm)要求连 `gdut` 后用统一身份账号完成网页认证。[校区入口说明](https://nic.gdut.edu.cn/info/1029/2401.htm)列出大学城/番禺为 `10.0.3.2`，龙洞/东风路为 `10.0.3.6`。本机实际访问前者得到 Dr.COM 登录页。

手机尚无浏览器，因此已准备私有 `local/wifi-gdut-20261004/Open-GdutLogin.cmd` / `.ps1`：用户运行后，用严格 USB SSH 建立仅监听本机 loopback 的 SOCKS 代理；先核对登录页所见来源等于手机 Wi-Fi 地址，再用独立 Chrome/Edge profile 打开原始学校认证页。用户在学校网页输入密码，工具不代填或保存认证凭据到项目文件；浏览器 profile/原始证据均只留忽略的 local。

首个启动指引依赖 pwsh，但用户终端无此命令。现已兼容系统 Windows PowerShell 5.1，完整 `-CheckOnly` 预检通过，包含代理监听进程归属、手机地址、门户来源与退出清理。cmd 只对所启动的 PowerShell 进程使用 ExecutionPolicy Bypass，不更改系统执行策略。

前次代理 curl 测试因主机 NO_PROXY 绕过代理，不能作为手机证据。强制 socks5h 并排除 no-proxy 绕过后，已核对正确来源；错误来源页面已删除。辅助脚本语法通过，代理端到端页面读取已验证。用户根据页面提示要求使用 `http://9.9.9.9/`，已改启动地址；实机 302 跳转到带手机 WLAN 参数的学校认证页，之后用户确认登录成功。

## 认证后实测

- 通过手机 wlan0 发出的外部 HTTP 返回 200，不再被重定向到认证页；Debian 官方站点 HTTPS 返回 HTTP/2 200，TLS 证书校验未关闭。
- `resolvectl query www.debian.org` 通过 wlan0 的 DNS 返回实际地址。
- 已有 timesyncd 在认证前持续超时；认证后重启服务，正常收到 Debian NTP pool 响应，`System clock synchronized: yes`、Stratum 1、实际收到两个包。设备仍使用 UTC，RTC 仍是 1970；这是系统时钟同步成功，不代表硬件 RTC 已修复。
- 临时 XFCE 测试因原设 20 分钟 RuntimeMaxSec 到时退出，Result=timeout；已清除失败测试状态，最终无 failed unit。没有修改桌面默认启动策略。
- TUN 是同组模块配置，文件存在；当前未加载、不安装任何穿透客户端。Tailscale 官方登录页与软件源首次连接探测均超时，仅能说明这些目标当前未打通，不能推断校园网永久封禁或替代整体外网结果。

## 待验收

首次门户认证、外网 HTTP/HTTPS、DNS、NTP 已通过。断线/重启后认证状态、24 小时无线稳定性及远程穿透未完成；没有为检验认证是否保留而主动断开已登录会话。用户明确用途为 MC Java 版、无 VPS、先考虑省钱，要求直接用校园 Wi-Fi 流量。

优先验证全球 IPv6 直连：手机具有动态全球地址和默认路由；以非特权用户在 WLAN 的该地址上临时监听 TCP 25565，只返回固定测试文本，不提供文件或游戏内容，15 分钟自动停止。本机访问通过。外部网页抓取工具不接受该 IPv6 URL，不能作为网络拒绝的证据；已协调用户使用另一台手机移动数据验证入站。IPv6 的公网格式、出站路由和本机连接都不等于校外入站已通过。原校园 DNS 对两个测试网站未返回 AAAA，尚未确定是记录缺失还是查询路径问题，不能据此判 IPv6 链路被封禁。

尚未部署 MC、不安装自动重登录/凭据持久化或穿透客户端；未扩容根文件系统。手机实测 aarch64、内存约 11 GiB，当前根文件系统约 3.9 GiB、剩余约 1.7 GiB，游戏世界容量需后续规划。具体服务端类型/版本、玩家规模和外部连入待确认。

私有原始证据入口 `local/wifi-gdut-20261004/`。AP、地址、校园账号、浏览器 profile 与原始门户内容不上传 GitHub。若需要撤销该关联，停止并禁用 `wpa_supplicant@wlan0`，保留配置供审计；USB SSH 不受影响。
