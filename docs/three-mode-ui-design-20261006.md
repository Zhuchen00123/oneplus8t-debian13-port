# 三段键：终端／仪表盘／电脑设计方案（2026-10-06）

状态：v2为实施前提案，现已部署，见[实施与回退](three-mode-ui-20261006.md)。用户原生实测后明确取消下档独立键盘按钮，使用输入框自动唤出；以下手动按钮讨论保留为原提案历史，不代表最终交互。用户确认上档触控终端和中档现有panel的第一版交互，下档要求手机适配更好的桌面；键盘须支持点按唤出和蓝牙实体键盘。电源键继续负责亮灭屏。

## 推荐选型

下档优先验证Phosh（手机界面）+ Phoc（Wayland合成器）+ Debian 13仓库的Squeekboard（屏幕键盘）。上档终端和中档panel的布局与功能按上一版保留；若采用该组合，三个视图共用Phoc会话，GTK/VTE终端和panel适配Wayland后端，下档显示Phosh应用概览及移动适配应用。三段键选择视图，电源键选择屏幕亮灭，两者独立。

当前面板与桌面通过两份LightDM单元互斥启动，`kebab-display`每次先停止原会话；新方案不能直接把这条命令绑定三段键，否则每次拨档都重建Xorg并关闭桌面应用。拟新增独立三模式会话及控制器，切换只隐藏／显示界面，不注销、不重启Xorg、不终止桌面程序。

这替代上一版“共享XFCE会话”的推荐，不等于只替换下档外观而保持Xorg不变。现有Xorg/XFCE作为完整回退路径保留；不在拨档时来回切Xorg与Wayland。当前panel的X11启动包装需要适配，不能直接把其GDK_BACKEND=x11传入Phoc会话。

手机尚未验证Phoc原生DRM/显示/触摸路径。应先检查是否支持嵌套测试，验证界面与键盘后，再协调有界原生会话测试及回退。嵌套成功也不能替代内屏、GPU、触摸与电源键实机验收。需测内存、CPU、渲染活动和用户感知温升；旧面板约177MiB图形PSS不能保证新方案占用。

## 三档交互

| 档位 | 呈现 | 状态保留 |
| --- | --- | --- |
| 最上／0 | 全屏Linux终端，内嵌触控键盘 | 命令、工作目录、滚动历史与任务保留 |
| 中间／1 | 当前三页只读仪表盘 | 页码和现有网络／健康快照逻辑保留 |
| 最下／2 | 优先Phosh手机桌面，手动屏幕键盘 | 已开的窗口、应用、文件操作保留 |

首次使用按真实档位显示；设备事件重连时读取当前轴值，不能等下一次拨动。事件丢失时重新查询，未知或磁干扰时保持最后确认视图，不把未知映射为上档。

驱动已有约三份样本去抖；视图层再等待档位停稳约0.6–0.8秒，期间最后档位覆盖前面的请求，避免上下拨动经过中档时短暂显示面板。所有切换串行、幂等，不因重复事件启动多份键盘或桌面。

屏幕熄灭时拨档只更新目标视图，不强制亮屏；下一次短按电源键直接显示新档位。屏幕亮灭仍仅由现有电源键服务控制，不新增Xorg/桌面独立自动消隐。面板熄屏继续暂停采样／重绘；终端后台任务和服务器服务不因熄屏或换档而暂停。

## 终端档

使用GTK3 + VTE构建竖屏终端页，不写终端仿真器。顶栏显示本机、普通用户和终端状态；中部是可滚动输出区；底部约30–35%高度是可收起键盘。键盘按键以约44–48逻辑像素为最低触控目标，最终以实机手指验收。

普通布局包含完整ASCII、数字和shell常用符号；独立快捷行提供Esc、Tab、Ctrl、Alt、方向键及常用组合，如Ctrl-C/Ctrl-D/Ctrl-L。Ctrl/Alt采用一次性锁定并有明显状态，长按才持续锁定；Backspace支持按住连续删除。键盘直接向本页VTE发送输入，避免终端失去焦点或按键被发送到别的窗口。

拖动输出区用于回看历史，长按进入选择／复制；提供粘贴、字体大小和键盘收起按钮。多行粘贴先预览，确认后送入终端，避免点击即执行末尾换行。默认普通用户shell，提权沿用sudo；不记录键盘内容或终端密码。

后端采用独立用户服务托管的tmux会话，图形终端只是客户端：换档不关闭它，图形程序崩溃后重新连接；独立后端避免随图形服务停止而被一并杀死。第一版提供单个会话，暂不叠加多标签、中文输入法、自动旋转或命令宏。

现场核查：xfce4-terminal、VTE共享库与Onboard存在；tmux可执行文件和VTE的GI typelib未发现，需要在实现阶段重新核验并补齐。未实测Onboard触控或自动弹出，不能把包已安装当作可用性验收。

## 仪表盘档

沿用现有panel的三页内容与刷新／过期策略，整合为共享GTK界面的页面；不会为了三模式重新写指标采集。隐藏终端键盘和桌面键盘，恢复上次面板页。界面故障时优先回到只读面板，保留USB SSH维修入口。

## 电脑档：手机桌面选型

| 候选 | 本项目判断 | 用途 |
| --- | --- | --- |
| Phosh + Phoc | 明确面向小屏、触控手机；GTK体系与现有panel/VTE技术相近；Debian 13提供arm64包 | 首选实机试验 |
| Plasma Mobile | 同样专为手机设计，是KDE/Qt方向的可选方案；本机尚无对应验证 | Phosh达不到实机目标时再比较 |
| XFCE + Onboard | 已有本机Xorg验收，但本质为传统桌面，放大控件不能替代手机适配 | 保留回退与外设维护环境 |

Phosh桌面以竖屏应用入口、任务概览及少量移动适配应用为主；不要求使用电脑式小图标、细窗口边框和密集菜单。触控与键盘都需能导航。不能保证所有Linux桌面应用自动变成手机界面；浏览器、文件管理器及设置需要逐个验证小屏和输入协议。

Squeekboard有用户会话D-Bus的显隐接口`sm.puri.OSK0.SetVisible`，可接固定“键盘”按钮，点击显示、再次点击收起；这是有官方接口的设计方向，尚未做本机集成。默认不强制因点击输入框自动弹出，防止遮挡内容；保留以后选择自动模式的余地。键盘出现时应给应用留出可见输入区，当前文本框不能被盖住。

终端档仍保留上一版内嵌终端键盘，由本页按钮控制；下档使用Squeekboard通用键盘。两者互斥，进入panel均隐藏。Onboard只保留在Xorg/XFCE回退中，不当作Phoc的通用键盘。Wayland原生应用和必要的XWayland应用需分别验收输入焦点及屏幕键盘兼容性，不承诺所有旧应用都能输入。

当前上游Phosh介绍页列出Stevia作为屏幕键盘组件，但本轮初始试验优先用Debian 13的Squeekboard稳定包，避免为了键盘升级整个系统。版本和依赖在实施前重新查证；中文输入单独设计和验收。

部署只选择必要软件包，不直接安装完整phosh-core/phosh-full环境：phosh-core包括NetworkManager等组件，可能扩展到已有校园网络管理范围。保留现有wpa_supplicant/校园维护、限充、USB SSH与服务器服务；Phosh/GNOME组件的电源键、自动休眠和显示消隐也必须与现有按键服务协调，不能让两个组件同时控制亮灭。

## 点按键盘与实体键盘共存

- 下档提供始终可找到的键盘按钮；弹出后可收起，输入框保持焦点。软键盘状态不因换档形成重复进程或覆盖另一个输入界面。
- 蓝牙键盘走BlueZ及内核HID输入，连接后作为实体键盘向当前普通用户图形会话输入；不是把字符绕到三段键服务。上档也接收同一实体键盘事件。
- 连接实体键盘后默认收起屏幕键盘，但按钮仍可手动唤出。断开时不丢失焦点和已输入内容，按钮继续可用；区分配对成功、连接成功和实际键盘事件，不能只看Connected就宣称可用。
- 支持字符、数字、符号、Ctrl/Alt/Shift组合、Tab、Esc、方向键、持续按键与释放；连接后不能误把触摸、三段键或电源键当作外接键盘。
- 检测实体键盘时忽略触屏、音量键、电源键、三段键及虚拟键盘设备，以真实键盘能力和连接状态判断。断连要解除残留修饰键状态，避免Ctrl一直按住。
- 需要实际键盘的首次配对/PIN、蓝牙范围内重连、模式切换、熄屏前后和服务重启测试。项目此前仅验证蓝牙地址初始化；无线配对及HID输入未验收，不能承诺本机现已支持。
- 蓝牙相关实际地址、配对材料和原始记录仅存受限本地，不发Git或图表。

旧维护桌面的20分钟RuntimeMaxSec会终止整个会话，与共享视图和保留窗口冲突。新方案建议取消这种整会话强退，改为桌面使用20分钟后提示；物理档位仍决定当前模式，电源键仍负责熄屏。持续亮屏与温升必须重新验收，再决定是否加入由统一亮灭服务执行的空闲策略。

## 实施与验收顺序

1. 补齐终端依赖，先独立验证VTE + 内嵌键盘：真实打字、符号、快捷键、复制粘贴、sudo和终端程序退出。
2. 审核Phosh/Phoc/Squeekboard最小依赖与既有服务冲突，先验证嵌套界面／手动键盘，再做有界原生显示／触摸实验；保留Xorg回退，不直接替换开机入口。
3. 验证上、中GTK界面在Wayland下的布局／输入，接入三段键；测试快速跨档、熄屏拨档、亮屏恢复、事件重连和图形异常恢复，确认终端任务及桌面窗口保留。
4. 协调真实蓝牙键盘配对、各档字符与组合键输入、断连重连和软键盘手动显隐，区分软件设计与硬件通过。
5. 比较旧面板与新会话的PSS、CPU及熄屏活动，协调真实手指操作和温升观察；不改充电、温控或服务器服务来掩盖开销。
6. 通过后迁移开机入口，保存旧面板单元和配置以便回退；整机重启另行协调，不作为本次设计动作执行。
