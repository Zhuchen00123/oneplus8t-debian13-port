### 1.5 本轮新证据：本机 EFS/NV 分区不是空的（L2）

用 `local/gps-oemnvbk-parse.py` 同算法只读解析 10/03 本机原厂分区备份（`backups/partitions-20261003-152513-342/`）：

| 分区 | 大小 | 非零占比 | OEMNVBK 记录 | 说明 |
| --- | --- | --- | --- | --- |
| `mdm_oem_stanvbk` | 10 MiB | 45.28% | 292 file 记录 / **94 个 /nv/item_files 路径** / 281 item 记录 / 35 个 id | 含 `mcfg/mcfg_autoselect_by_uim`、`mcs/tcxomgr/{ft_table_wwan,ft_table_gps,xo_factory_cal_data,field_cal_params,…}`、`gps/cgps/me/gnss_config` |
| `mdm_oem_dycnvbk` | 10 MiB | 3.09% | 1 file / 22 item | 动态 NV |
| `mdm1oemnvbktmp` | 2 MiB | 39.38% | 52 file / 51 path / 51 item | 头在偏移 528 |
| `mdm1m9kefs1` | 2 MiB | 99.59% | — | 头部 `IMGEFS1F`；字节分布近似均匀（**高熵**，非 0x00/0xFF 填充） |
| `mdm1m9kefs2` | 2 MiB | 99.6% | — | 同上 |
| `mdm1m9kefs3` / `modemst1` | 2 MiB | 0% | — | 全零 |

对照社区 KB2003 记录（`sources/bringup/docs/research/MODEM.md` §4.4.1 与 §5）：其 `efs1.bin` 2 MiB 仅 **179** 字节非零，`modemst2/fsg/fsc` 全零，因此「NV 未 provision → DeviceNotReady → 射频不上线」是该机的首要解释。

**结论与边界**：
- 本机 KB2000 的**闪存侧** NV/EFS 明显不是空白（原厂 Android 出身），所以**社区那套「空白 EFS 导致 DeviceNotReady」的因果不能直接套用**。
- 但**闪存非空 ≠ modem 看得见**：PCIe flashless modem 的 EFS 由 AP 在 Sahara 阶段喂入；当前 `/lib/firmware/sdx55m/efs{1,2,3}.bin` 是固件 tar 里的 **512 B 占位**（[GNSS §1.4](sdx55-gnss-feasibility-20261110.md#L69-L85)），而不是这 2 MiB 真实镜像。也就是说：**「modem 侧 NV/EFS 视图」与「闪存侧内容」是两件事，必须分别取证**。
- 解析器是容错扫描（复刻本项目既有脚本），计数可能含伪记录；`IMGEFS1F` 头与高熵是独立观察。**不能**据此断言「NV 已 provision 且可用」——那需要 A1/A2 的 modem 侧判定。

3. **camping vs registered 未区分**：决定下一步是「控制面/注册」还是「数据面」。
4. **modem 侧 NV/EFS 视图未知**：闪存侧非空（§1.5）与服务侧 512 B 占位并存，这是本机独有、且**不需要换内核**就能验证的分叉。
5. **host 用户态全缺**：MM 未装、两个补丁未移植、QMAP 未配、`qmi-proxy` 经 QRTR 长驻超时（[§9.4](sdx55-gnss-feasibility-20261110.md#L323-L328)）→ **必须自写单进程 WDS 客户端**，不能拿两个 `qmicli` 进程当同一 owner。
6. **无 runner/锁/grant 底座**：设计中（工作流报告 §4），未实现。首个 W1 实验若手工执行，门禁是「人 + prompt + 人工核对」，**不是技术强制**（prompt 自己已声明这点）。

## 4. A 路线下一步（编号计划）

原则：一个假设、一个变量、有前像、有预算、有停止条件、有恢复；**先只读，再可逆上电，再数据面；MM 最后**。

### A1（R1，只读盘点）——建议立即批准

目的：把 §1 的 L1/历史全部换成 L0 新鲜回执，并判定 §1.3 的 GNSS 空转风险。

- **被动**：`uname -r` / boot_id / uptime；`/proc/config.gz` 过滤 MHI/WWAN/QRTR/LOC 相关；`lsmod`（是否已加载 `mhi_pci_generic`）；`ls /sys/bus/mhi/devices`（是否只有 Wi-Fi 的 `mhi0`）；`lspci -s 0002:01:00.0 -k`；`ls /dev/wwan*`；`qrtr-lookup`；`/lib/firmware/sdx55m/` 清单（大小/是否存在）；`systemctl is-enabled/is-active`：`mhi-efs-sync` / `pm-service-native` / `tqftpserv-sdx55` / `kebab-gps` / `kebab-geoclue-agent`；`/run/kebab-gps.json` 与 `/run/kebab-cell*.json` 摘要（**坐标脱敏**）；`/etc/modprobe.d/90-kebab-server.conf` 是否存在及内容；`ip route/rule`、DNS、IPv6 现状（只读）；`dpkg -l` 过滤 qmi/mm/qrtr；`systemctl --failed`；温度、电量、限充状态、taint。
  - 若 SDX55 未 up：**不 modprobe**，只记录「未 up + GNSS 消费端状态」。
  - 若 SDX55 已 up：白名单 QMI get 才有意义。
- **白名单 QMI get（每项一次、串行、单命令 `timeout 8`、总预算 ≤120 s；任一失败即记录并继续）**：
  `--dms-get-operating-mode`、`--dms-get-band-capabilities`、`--uim-get-card-status`、`--nas-get-serving-system`、`--nas-get-signal-info`、`--nas-get-system-info`、`--dms-get-manufacturer`、`--dms-get-revision`、`--pdc-list-configs=active`。
  - **身份类只输出布尔判定**（例如「IMEI/ESN 字段是否全零或未提供」），**绝不打印、绝不落盘原始标识**；ICCID/IMSI 同规则（只留长度与是否可读）。
  - 不用 PIN、不 `--uim-verify-pin`、不 `--dms-set-operating-mode`（后者是 W1，属 A2）。
- **禁止**：装包、start/enable 任何服务、modprobe、reset、online/attach、写 PDC、改路由/DNS/IPv6、重启。
- **预算/时窗**：≤15 分钟；同一维护锁；不占 LOC owner（不 start/stop LOC，不换 lock/opmode）。
- **恢复**：无写，无需恢复；仅可能留下 QMI client 会话（QMI get 会创建 client 并唤醒 modem），记录后自然释放。
- **判据**：给出「SDX55：up/未 up」「GNSS：真出 fix/空转」「SIM：有卡/无卡/PIN 锁」「radio：camping/registered/offline」四项明确结论，**unknown 不得当 pass**。

### A2（W1，可逆上电 + 控制面读数）——需单独批准

目的：用**已知四步序列**把 modem 拉起，读控制面状态；**不建 bearer**。

- 动作白名单（顺序固定，每步有回执）：`systemctl start pm-service-native tqftpserv-sdx55` → `modprobe mhi / mhi_sahara_modem / mhi_wwan_ctrl / mhi_pci_generic` → `systemctl start mhi-efs-sync` → 有界等待 ≤60 s → 只读核对 mission mode / `mhi1` 通道 / `/dev/wwan*` / qrtr node 3 / dmesg 无 errfatal。
- 然后：`--dms-get-operating-mode`；如 offline，**可选一步** `--dms-set-operating-mode=online`（计入预算，一次，失败即停），再读 `--dms-get-band-capabilities`、`--nas-get-serving-system`、`--nas-get-signal-info`、`--uim-get-card-status`、`--pdc-list-configs=active`、`--pdc-list-configs=software`。
- **不做**：WDS/bearer、APN、MM 安装、QMAP、任何 NV/EFS 分区写、任何 `-g/-W`、任何 PDC 激活（`--pdc-activate-config` 属 W2）。
- 预算：≤10 分钟；流量预算 0（不建 bearer 就不该有蜂窝字节，用 counters 断言为 0）。
- 恢复：`systemctl stop mhi-efs-sync` → `modprobe -r mhi_pci_generic mhi_wwan_ctrl mhi_sahara_modem`（顺序反）→ `systemctl stop tqftpserv-sdx55 pm-service-native` → 核对 Wi-Fi `mhi0`、五业务、无 failed、boot_id 不变。
- 停止：ERRFATAL、PCIe linkdown、`Device died`、EFS 服务异常、GNSS 心跳回归、USB 管理回归、保护业务退出/重启、预算或温度超限。

### A3（W1，数据面）——独立批准，前提是 A2 证明 radio 可用

- 单客户端自写工具（Python `AF_QIPCRTR`，同 `gps-r7-inject.py` 的成熟做法）：WDS bind(endpoint=发现值) → start → indications → status → stop；**同一 client 完成全程**（apollo 说明：两个独立 `qmicli` 不共享 WDS client）。
- 端口/endpoint/接口名一律**本机发现**，不照抄 apollo 的 `iface=4` / `mux 0` / `mhi_hwip0` 常量。
- 网络：独立源地址策略路由表 + 目标白名单（单个 HTTPS），表内禁止落回主表；**不改默认路由/DNS/IPv6/代理**；显式证明「流量走蜂窝 netdev + WDS 字节增长」，HTTP 200 单项不算通过。
- 预算（待批准参数）：≤10 分钟，下行 16 MiB + 上行 1 MiB，蜂窝接口总字节硬上限 40 MiB；若套餐不允许则降级并标注「未覆盖 >10 MB 卡死故障」。
- QMAP：raw-IP 先试一次有界下载；若复现 ~10 MB 卡死，再单独申请 QMAP/mux（属新变量）。

### A4（R0，离线适配）——可与 A1 并行，无需设备授权

- 取 Debian trixie `modemmanager` 源码（走项目既有代理），判断两个补丁是否已被上游等价实现；打独立 deb 到隔离目录（如 `local/mm-candidate-20261112/`），**不安装、不 enable**。
- 逐字节 diff apollo 与本机 bringup 的 4 个文件（fusion.rules / ignore-efs.rules / mux.conf / UPSTREAM-NOTES）。
- 设计「MM 首次启动不得自动拉起」的拦截：drop-in `ConditionPathExists` / `ExecStart=` 覆写 + `systemctl mask` 序列；预置 `77-mm-ignore-sdx55-efs.rules` 的正确端口名（本机需覆盖实际 EFS 设备，不能只硬编码 `wwan0efs0`）。
- 产出：候选包 SHA、补丁适用性结论、前像/恢复脚本草案（**不执行**）。

### A5（W2，高风险，仅在 A2 显示「NV 无效/DeviceNotReady」时才提）

把 `/lib/firmware/sdx55m/efs{1,2,3}.bin` 从 512 B 占位换成**本机自己的** 2 MiB EFS 镜像（来源：10/03 备份或一次新的 EFS-sync 导出）。理由见 §1.5。属「EFS 启动输入替换」，必须：前像备份 + 单次 + 有界 + 明确回滚（装回 512 B 占位）+ 不停 server 服务的时窗。**本轮不申请**。

## 5. 需要的用户输入

1. SIM：是否可提供一张可用卡？插在哪个槽？套餐/流量/漫游是否允许一次 ≤40 MiB 的测试？（不告诉我 PIN；PIN 只在你本地输入）
2. 物理在场：A2/A5 需要有人能确认屏幕与 USB；可用时窗（建议 10 分钟起步，避开夜间长任务）。
3. 优先级选择：先「证明 camping/注册」（A2）还是先「证明一次数据往返」（A3，风险与资费更高）？建议 A2。
4. 是否允许 A4 离线拉取 MM 源码并构建独立 deb（不安装）。
5. 温度/电量门限是否采用报告 §6.2 的待批准参数（电池 <30% 停、起始 ≥40 °C 停、运行 ≥42 °C 或 Δ≥3 °C 停）。
6. 是否同意把「SDX55/EFS 常驻自启」作为**独立**条目（它同时影响 GNSS 可维护性），不与蜂窝混在一批。

## 6. 本轮明确未做

- 未连手机、未 SSH、未发任何 QMI、未 modprobe、未 start/stop/enable 服务、未装包、未写文件到设备。
- 未刷写/备份/恢复任何分区，未动 GPT、未重启、未改路由/DNS/IPv6/代理、未动限充与温控。
- 未安装 ModemManager、未移植社区补丁、未创建 runner/grant/锁。
- 未验证：本机当前 boot 的 SDX55/GNSS 状态、SIM、注册、数据面、MM 候选兼容性、Fastboot 读回能力、当前恢复组新鲜度。
