# EmbeddingGemma 2 ONNX Q8 ARM64 试跑

2026-10-07在KB2000、Debian 13 ARM64进行独立CPU短测。模型、依赖和合成脚本已验证可运行；适合低并发文本检索与后台图片索引，未完成生产服务、真实资料质量或长期温升验收。

## 固定来源

模型为onnx-community/embeddinggemma-2-ONNX，提交daa72c51243991dfcaf9f9137d2c573d8f7790c0；只使用Q8文本与视觉编码器，音频不加载。Node20.20.2、Transformers.js4.3.1、onnxruntime-node1.30.0。来源见[sources.lock.json](../sources.lock.json)，[模型文件清单](../config/embeddinggemma-q8-model-manifest.json)和[公开图片样例清单](../config/embeddinggemma-q8-sample-manifest.json)。模型文件逐项大小及SHA-256双端一致。

## 实测结果

普通大核CPU4单线程，inter-op1，Nice10，每次请求间隔5秒；下列时间不含主动等待和模型加载。

| 场景 | 预处理+推理时间 |
| --- | --- |
| 短中文查询，17 token | 0.587秒 |
| 三份文本，填充至26 token | 1.057秒/批 |
| 两条中文查询 | 0.710秒/批 |
| 32 token截断文本 | 0.756秒 |
| 128 token截断文本 | 1.567秒 |
| 640×480猫图 | 7.918秒 |
| 614×410狗图 | 8.072秒 |
| 图像已索引后的四条文本查询 | 0.940秒/批 |

图片处理预算70视觉token。峰值进程RSS：文本743.1MiB，文本+视觉1170.7MiB；systemd cgroup峰值分别531.8和791.7MiB，计量方式不同。短测CPU温度采样最高分别61.6°C和55.8°C，电池最高38.0°C和38.1°C；没有测表面温度，不能据此宣称长期热安全。

文本与图像输出均为768维有限、单位范数向量。两条中文查询在三份合成文档中命中预期项；中英文各两条查询在猫/狗两张图片中全部命中预期项，图像间余弦约0.6715。这仅是功能冒烟，不能当公开基准或普遍准确率。

初始两线程、不限制CPU亲和的连续短请求约0.32秒，但CPU7温度采样升至74°C，触发预设65°C停止条件，整轮未通过。小核单线程文本功能通过，但128 token约8秒、512 token约28秒；140视觉预算第一张图约88秒，随后停止该轮，未完成跨模态验收。不能只引用最快请求而忽略温度与未完成测试。
