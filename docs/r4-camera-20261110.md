## 2. PHY 类型 / lane / link frequency 结论（诚实边界）

- **无法用 DT/vendor 源码确证**：vendor CSIPHY 的 3-phase 是运行时 `cam_cmd_csiphy_info->csiphy_3phase`（由 sensor 驱动传入，见 `cam_csiphy_core.c:317-330`），`kona-camera.dtsi` 的 csiphy 节点只声明 `qcom,csiphy-v1.2.1` 硬件版本；原厂 DTBO 与 vendor DTS 都不含 lane/PHY 字段；两套公开内核树都没有 imx586 驱动源码；原厂 super 已改为 Debian ext4，vendor 分区配置不可得。
- **采用的假设（已写进 DTS 注释与驱动）**：C-PHY、3 trio、link freq 698,395,833 Hz。依据是同一 IMX586 模组在 hotdog 上的实测结论（`docs/evidence/2026-08-09…`：“three C-PHY trios”，4000×3000 RAW10 实拍通过）与 hotdog 恢复出的 Qualcomm IMX586 模式描述。
- **可切换**：驱动同时接受 D-PHY 4 lane；若候选启动后 C-PHY 无帧，只需把 endpoint 改成 `bus-type = <MEDIA_BUS_TYPE_CSI2_DPHY>; data-lanes = <0 1 2 3>;` 即可验证另一假设，不必改驱动。
- 该结论属于“待实测”，**不是已确证**。

## 3. 阶段 1：前摄结果

- 路径：`imx471 24-0010` → `msm_csiphy4:1` → `msm_csid0:1` → `msm_vfe0_rdi0` → `/dev/video0`；sensor→csiphy 链接为 dts 中的 ENABLED+IMMUTABLE。

## 2026-11-11 凌晨续（候选机试机与失联）

00:22 用 `boot-r4-camera.img`（r4 内核 + `imx586=y` + C-PHY 3-trio DTS，**被弃用的第一版**）试机，`fastboot boot` 返回成功但设备再未枚举，随后失联至今。事后拆它的 DTB 才发现：那张镜像把 `pm8008_l7` 钉死在 2.896 V，还挂了一个**没有出处**的 `regulator-cam-rear-vana` 在 tlmm 26 上（事故文档 §18.59）；这两处现在都不存在。
