# MP2762A 限充驱动候选（2026-10-04）

本候选只做一次停充，并在**30秒后开始尝试自动恢复**，用于验证真实寄存器与 USB 供电。恢复受内核调度和 I²C 可用性影响，30秒不是硬件保证的停充上限。2026-10-04 已在隔离候选内核上完成一次实机停充、自动恢复和重启回滚；它还不是80%限充实现，也没有装进生产 r2 镜像。

## 代码行为

- 扩展既有 `mp2762-otg-regulator`，不抢占同一个 I2C 地址。共用互斥锁串行化 OTG 和充电访问；停充期间拒绝 OTG 上电。隐藏手工 `bind/unbind`，有序卸载/关机时尝试恢复。
- 首次试验只在这些实读条件都满足时继续：CHG_EN原本为开、BATTFET开、OTG和SUSP关、无寄存器复位/看门狗命令、看门狗时长为0、REG13报告输入电源良好且无系统/电池欠压。
- 用读改写清除REG08 CHG_EN；不碰其它充电配置、REG09、OTP或电池保护。成功写后读回。二次请求不能延长计时。
- 根系统参数 `allow_charge_test` 默认为 `false` 且只读；只读REG08/09/13快照始终可用。实机试验只在一次性测试启动参数中启用此门控，回滚后的默认启动不启用。
- 30秒到时自动恢复原CHG_EN位并读回确认。I²C错误/读回不一致时保留恢复任务，每秒重试并报告状态；若设备解绑或正常关机，会再尝试一次。
- 断电、内核崩溃、芯片移除或持续I²C故障时，软件无法保证完成恢复。当前测试候选遇到此类条件可能停在禁止充电状态，需要实际板上确认恢复方案。手册显示开机/看门狗复位会恢复器件默认寄存器，但本机OTP默认值未知，不能拿它当作已验证的救援手段。

## 已有验证

- 纯C寄存器核心以主机 GCC ASan/UBSan 测过65,813种控制寄存器/看门狗/状态组合，以及读写故障、写操作结果不确定、读回错误、重试恢复和配置冲突。
- 完整修改驱动作为外置测试模块，使用运行中 r2 的配置和头文件，以 Clang `W=1` 编译通过；模块 vermagic 与 `7.2.0-kebab-debian13-r2+` 匹配。没有安装或加载到手机。
- 候选源提交为 `ab77fc2f590584426315a10d47e4390f960f9f0a`，补丁见 [候选补丁](../patches/local/0005-regulator-mp2762a-bounded-charge-test.patch)。已从项目固定社区源重新应用全部 r2 补丁和本补丁，完整内核版本为 `7.2.0-kebab-debian13-r2-charge-candidate+`；DTB、578 个模块、server initramfs 和 RAM 救援 initramfs 均已生成并完成离线审计。
- 候选持久组位于 `artifacts/server-charge-candidate-20261004/ready/`，RAM 组位于 `artifacts/boot-charge-candidate-20261004/rescue-final/`。候选持久启动已在手机上完成一次只读启动和一次带测试参数的启动；RAM 救援组仍未做硬件启动验证。

## 实机有界测试（2026-10-04）

- 测试启动参数只为 `mp2762_otg_regulator.allow_charge_test=1`，写入前对 `boot_a` 的测试镜像前缀回读校验通过；测试结束后恢复默认只读镜像，回读一致并重启。
- 测试前快照为 `REG08=0x16`、`REG09=0x4c`、`REG13=0x0f`。单次写入 `inhibit-charge` 后回读为 `REG08=0x06`，`owned=1`；电池状态为 `Not charging`，电流读数为 `0`，USB 电源在线且 `usb0` 载波保持为 `1`。
- 约30秒后驱动自动恢复，回读为 `REG08=0x16`、`owned=0`；电池状态恢复为 `Charging`，USB 在线和载波持续为 `1`。测试脚本退出码为0，未触发手动恢复或重启恢复。
- 回滚重启后的默认快照为 `allow_test=0 owned=0 last_error=0`，`charge_behaviour` 权限为只读 `444`，电池状态为 `Charging`，健康 timer active，failed units 为空。
- 证据保存在忽略目录 `local/charge-candidate-20261004/charge-test-run.txt`、`candidate-charge-test-final.txt` 和 `candidate-charge-test-post-reboot.txt`；这些记录不含设备序列号或私有认证信息。

## 试验与验收边界

后续若做更长时间、低电量跨阈值或插拔/重启组合试验，仍应在校园 USB/RNDIS 与 SSH 活跃、USB输入源稳定、电池有充电电流且用户可在旁观察时进行：先读REG快照与电源/电池状态，再仅发一次 `inhibit-charge`，观察 USB网络、SSH、显示/系统负载和充电电流，检查自动恢复以及寄存器快照。异常立即请求 `auto`，系统重启是次级恢复手段；若 USB 供电中断，需靠电池维持运行。任何试验都不保证长期自动恢复。

此候选尚未证明实机的完整状态位语义、热保护行为、功耗或长期 USB稳定性，也没有用低于80%的实际充电循环验收。即使短试验通过，还要先建立小型用户态滞回策略（80%停、75%恢复）并测电量读数、重启/插拔和长时间负载，才可评估正式部署。当前健康监控继续明确报告 `charge_limit_enforced=false`。
