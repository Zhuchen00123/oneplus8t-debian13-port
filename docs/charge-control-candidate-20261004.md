# MP2762A 限充驱动候选（2026-10-04）

本候选只做一次停充，并在**30秒后开始尝试自动恢复**，用于验证真实寄存器与 USB 供电。恢复受内核调度和 I²C 可用性影响，30秒不是硬件保证的停充上限。它还不是80%限充实现，没有装进生产 r2 镜像，也没有通过候选路径写手机充电寄存器。

## 代码行为

- 扩展既有 `mp2762-otg-regulator`，不抢占同一个 I2C 地址。共用互斥锁串行化 OTG 和充电访问；停充期间拒绝 OTG 上电。隐藏手工 `bind/unbind`，有序卸载/关机时尝试恢复。
- 首次试验只在这些实读条件都满足时继续：CHG_EN原本为开、BATTFET开、OTG和SUSP关、无寄存器复位/看门狗命令、看门狗时长为0、REG13报告输入电源良好且无系统/电池欠压。
- 用读改写清除REG08 CHG_EN；不碰其它充电配置、REG09、OTP或电池保护。成功写后读回。二次请求不能延长计时。
- 根系统参数 `allow_charge_test` 默认为 `false` 且只读；只读REG08/09/13快照始终可用。此门控只供之后经核准的候选试验，当前没有开机参数启用它。
- 30秒到时自动恢复原CHG_EN位并读回确认。I²C错误/读回不一致时保留恢复任务，每秒重试并报告状态；若设备解绑或正常关机，会再尝试一次。
- 断电、内核崩溃、芯片移除或持续I²C故障时，软件无法保证完成恢复。当前测试候选遇到此类条件可能停在禁止充电状态，需要实际板上确认恢复方案。手册显示开机/看门狗复位会恢复器件默认寄存器，但本机OTP默认值未知，不能拿它当作已验证的救援手段。

## 已有验证

- 纯C寄存器核心以主机 GCC ASan/UBSan 测过65,813种控制寄存器/看门狗/状态组合，以及读写故障、写操作结果不确定、读回错误、重试恢复和配置冲突。
- 完整修改驱动作为外置测试模块，使用运行中 r2 的配置和头文件，以 Clang `W=1` 编译通过；模块 vermagic 与 `7.2.0-kebab-debian13-r2+` 匹配。没有安装或加载到手机。
- 候选源提交为 `ab77fc2f590584426315a10d47e4390f960f9f0a`，补丁见 [候选补丁](../patches/local/0005-regulator-mp2762a-bounded-charge-test.patch)。已从项目固定社区源重新应用全部 r2 补丁和本补丁，完整内核版本为 `7.2.0-kebab-debian13-r2-charge-candidate+`；DTB、578 个模块、server initramfs 和 RAM 救援 initramfs 均已生成并完成离线审计。
- 候选持久组位于 `artifacts/server-charge-candidate-20261004/ready/`，RAM 组位于 `artifacts/boot-charge-candidate-20261004/rescue-final/`。两组仍标记 `hardware_boot_verified=false`，尚未写入手机。

## 试验与验收边界

实机试验应在校园 USB/RNDIS 与 SSH 活跃、USB输入源稳定、电池有充电电流且用户可在旁观察时进行：先读REG快照与电源/电池状态，再仅发一次 `inhibit-charge`，观察30秒内 USB网络、SSH、显示/系统负载和充电电流，检查自动恢复以及寄存器快照。异常立即请求 `auto`，系统重启是次级恢复手段；若 USB 供电中断，需靠电池维持运行。任何试验都不保证长期自动恢复。

此候选尚未证明实机的状态位含义、热保护行为、功耗或 USB稳定性，也没有用低于80%的实际充电循环验收。即使短试验通过，还要先建立小型用户态滞回策略（80%停、75%恢复）并测电量读数、重启/插拔和长时间负载，才可评估正式部署。当前健康监控继续明确报告 `charge_limit_enforced=false`。
